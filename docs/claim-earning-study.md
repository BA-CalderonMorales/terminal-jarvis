# Study: earning the claims terminal-jarvis makes about other agents' tools

> Historical study of 0.1.21. Release 0.1.23 replaces the frozen freshness
> comparison with a runtime UTC clock and downgrades expired verification.
> The current inventory uses `runtime-gate`; counts and `frozen` findings
> below describe the original audit. See the
> [launch-policy decision](architecture-decision-records/launch-policy-and-lifecycle-2026-10-29.md).


`release/0.1.21`, working tree on top of `0c312d6`. Windows (`win32-x64`) is a
first-class target and this study was mostly executed on a Windows host with a
clean `PATH`. Three deliverables, each with a re-runnable artifact and a proof
that the old behavior fails and the new behavior passes.

The catalog is a few hundred machine-readable assertions about software this
repository does not own. This study makes one of them stop being a guess, and
closes one pipeline hole where the same class of guess had already cost a
release.

## The four questions, answered before changing anything

**1. What would a top professional do here that nobody asked for?**
Write down *which* assertions are held up by something executable and which are
held up by nothing, as a generated artifact, so the answer survives the next
person. Then pick the worst ratio and turn it into a measurement. The
unrequested part is the inventory: the repo can be wrong in hundreds of small
ways and only notice the ones a test happened to hard-code.

**2. What is the rawest material to start from?**
The manifest keys themselves: `harnesses/<name>/{index.toml,<capability>/index.toml}`
and `gates/<name>/index.toml`. They are the product's trust surface. The
pre-fix bytes are recoverable exactly (`git show 0c312d6:...`), which is what
makes an old-fails/new-passes proof possible without rewriting history.

**3. Which specific methods and tools?**
`catalog::validate` and its `truth`/`command_truth`/`effect_truth` rules (the
catalog shape gate), the real `terminal-jarvis` binary as the loader, `git
show`/`git worktree` to rebuild the pre-fix tree, `cargo clippy -D warnings` and
`cargo test --all-targets` on Windows, and a Python generator over `tomllib`.

**4. What, other than me or you, would show the result is right?**
The built binary's exit status on a stand-in catalog; the Windows compiler's
own verdict on the pre-fix tree; the catalog shape gate; and a fresh checkout of
the committed generated artifacts. Each is named and used below.

## D1 — a generated claim inventory with a verdict

**Artifact:** `docs/claim-inventory.tsv`, generated by
`scripts/python/catalog/logic/claim-inventory.py` (dispatched as
`scripts/python/catalog/index.py claim-inventory`). One row per asserted key:

```
subject  field  kind  value  held_by  basis  verdict
```

`subject` is `harness:<name>`, `harness:<name>/<capability>`, or `gate:<name>`.
`kind` is the sort of claim (identity, narration, provenance, support-state,
risk-class, platform-scope, execution-shape, freshness, environment,
install-source). `held_by` names the mechanism that fails closed when the value
is wrong (a shape-gate rule, the runtime platform guard, or a compile-time
constant). `basis` is `evidence` or `assertion`. `verdict` folds them into one
grep-able word:

| verdict | meaning |
|---|---|
| `witnessed` | a recorded real execution backs the value (`support=verified`) |
| `gate` | an executable cross-field invariant constrains the value |
| `inert` | a gate covers the field, but a higher-precedence guard makes the row unreachable, so the value can never be exercised |
| `frozen` | the value is compared only against a compile-time constant, so it cannot drift into a measurable failure |
| `external` | provenance confirmable only outside this repository |
| `asserted` | human narration; nothing here executes it |

**Rerun:** `python3 scripts/python/catalog/index.py claim-inventory` rewrites it;
`--check` fails when the committed file is stale. The check is wired into
`scripts/bash/verify/logic/verify.sh` step `[7]`, and `.gitattributes` pins LF
for `docs/*.tsv` so a Windows checkout cannot make it look stale.

**What it found (2,887 claims).** `asserted=494, external=225, frozen=225,
gate=1791, inert=123, witnessed=29`.

- **The platform-scope class.** 225 rows carry a `platforms` claim. Exactly one
  is `witnessed`: `hermes:headless = ["linux-x64-gnu"]` — the row the repo
  already knew about, now the model instead of the exception. 123 are `inert`
  (a non-empty scope on a `stub`/`disabled` row, where `guard_policy` refuses
  before the platform check ever runs). 101 are `asserted`: 93 executing rows
  with `platforms = []`, which disables the guard, claiming to run anywhere —
  six of them `verified`, a run on one host generalized to every platform — plus
  8 `unknown` rows, which `guard_policy` admits once a terminal session consents
  and whose empty scope the shape gate explicitly permits. This is the rest of
  the hermes class, and it is exactly where D2 landed.
- **A mechanism is chosen by schema, capability, and support state.** `held_by`
  names the thing that fails closed, so it cannot be inferred from the field
  name: the gate loader parses `gates/*/index.toml` instead of running the
  catalog shape gate over it, and `effect_truth` constrains `effect`/`network`/
  `interaction` only on the `download`/`update`/`ui`/`yolo` arms (or on a
  `stub`/`manual` row). The first pass claimed `gate:identity`,
  `gate:command-shape`, and `gate:effect-class` in both places — 92 rows of
  overstated mechanism, now `asserted`.
- **`freshness` is frozen.** All 225 rows share
  `verified_at = "2026-08-05T00:00:00Z"`, and `catalog::logic::freshness`
  compares it to the compile-time constant `AS_OF` (also `2026-08-05T00:00:00Z`).
  The "support evidence must be fresh" rule can therefore never go stale: it
  measures a constant, not a clock. Marked `frozen`.
- **`provenance` is external.** All 225 rows share
  `source = "internal:phase-01@fab5848"`. The commit `fab5848` exists, but the
  string is not evidence that any row's behavior was observed; marked `external`.
- **`install-source` is asserted.** 31 `package` values name npm packages
  (`@openai/codex`, `@sourcegraph/amp`, …) that nothing in this repo checks
  against the registry. Marked `asserted`. A future pass can make these earned
  with `npm view`; that decider is named here, not yet used.

## D2 — the POSIX-shell platform claim, falsified and hardened

**The claim with the worst confidence-to-evidence ratio:** 23 `*/version` rows
declared `support = verified|expected` and `platforms = []` (runs anywhere,
guard disabled) yet ran `command = "sh"`, `args = ["-c", "<tool> --version"]`,
`executable = "sh"`. On a clean Windows `PATH` there is no `sh`
(`C:\Program Files\Git\usr\bin` is not on it), so the probe cannot start and the
guard — disabled by the empty list — cannot save it. The claim was false and
unfalsifiable at once.

**Fix, in two halves.**
- Code: `catalog::logic::command_truth` gained a rule —
  `platforms.is_empty() && claims_execution(support) && executable in {sh,bash}`
  is an error. Unit-tested in `src/catalog/tests/command_truth_rules.rs`
  (`sh`/`bash` flagged; `sh` narrowed to `linux-x64-gnu` allowed; `disabled`
  allowed; a shell-free executable allowed).
- Data: the 23 rows now call the binary directly
  (`command = "<tool>"`, `args = ["--version"]`, `executable = "<tool>"`).
  `docs/support-matrix.md` regenerated; `find . -name index.toml | grep sh` no
  longer matches a version probe.

**Old-fails / new-passes, one command:**

```
scripts/bash/verify/index.sh claim-earned --from 0c312d6
  new binary vs the stand-in:  refused 24 POSIX-shell claims
  new binary vs the real catalog:  accepted
  old binary from 0c312d6 vs the stand-in:  accepted the stand-in
```

The stand-in is regenerated from the catalog: the script copies `harnesses/` to
a temp tree and wraps every executing `*/version` row back into the pre-fix
`sh -c` shape, so it cannot drift from the class it stands for. The new binary
is the real loader (`TERMINAL_JARVIS_CATALOG` → `catalog::load`); the old half
builds the pre-fix tree in a `git worktree` and runs the same binary. The
stand-in's rejection is witnessed a second time by the catalog test
`no_row_claims_platform_independence_through_a_posix_shell`
(`tests/catalog/tests/truth.rs`), which fails on the pre-fix catalog and passes
on the committed one.

## D3 — the Windows strict-clippy hole, and the line-endings gap

**The hole:** the repository's only `-D warnings` gate is Linux CI
(`.github/workflows/ci.yml` → `scripts/bash/verify/index.sh verify` step `[2]`).
`win32-x64` is a supported target, but a warning that fires only on Windows — a
dead-code warning on a helper used solely by unix-gated tests — reached the
release with nothing to catch it. `cargo clippy --all-targets -- -D warnings`
on the pre-fix tree fails with 12 + 19 + 2 deny-warnings errors across the lib,
bin, and test targets; the fix scopes the unix-only test support to `unix`
without gating any coverage away (the pure
`heartbeat_stops_promptly_when_the_scan_ends` test is un-gated so it still runs
on Windows; `src/gates/tests/util.rs` and the pty/TUI tests are `#[cfg(unix)]`
because the behavior they exercise is unix-only).

**Old-fails / new-passes, one command:**

```
scripts/bash/verify/index.sh windows-clippy --from 0c312d6
  windows-clippy: pre-fix tree at 0c312d6
  old: refused (36 deny-warnings errors)
  windows-clippy: working tree
  new: clean (strict clippy passes)
  windows-clippy: ok
```

Recorded on a Windows checkout, where the pre-fix tree is the half that fails.
The proof is host-bound by construction: where the pre-fix tree passes strict
clippy (a Linux host) it exits nonzero with `there is no warning to deny`, so a
passing baseline — or a working tree that fails — can no longer be recorded as a
passing contrast.

**The pipeline half:** `.github/workflows/ci.yml` gained a `windows-verify` job
on `windows-latest` that runs the same two commands the fix was proven with,
`cargo clippy --all-targets -- -D warnings` and `cargo test --all-targets`, so
the hole cannot reopen on the next Windows-only warning.

**The `[7]` line-endings gap, closed.** The generated support report is compared
byte-for-byte (`cmp`) against the checked-out file; with `core.autocrlf=true`
(a fresh Windows checkout has it) the checked-out file is CRLF while the
generator writes LF, so `--check` reports a stale artifact that is not stale.
`.gitattributes` pins `docs/support-matrix.md` and `docs/*.tsv` to `text eol=lf`.
Verified by cloning a scratch repository with `core.autocrlf=true` and reading
the checked-out bytes back as LF. This also protects the new claim inventory.

## External deciders actually used

- **The catalog shape gate** — the new binary refuses the POSIX-shell stand-in
  with 24 named errors; the real catalog loads.
- **A Windows host on a clean `PATH`** — the pre-fix strict-clippy failure and
  the fixed tree's `cargo clippy --all-targets -- -D warnings` success, plus
  `cargo test --all-targets` at 545 tests, 0 failed.
- **The compiler's verdict on the pre-fix tree** — rebuilt in a `git worktree`
  at `0c312d6`, not reconstructed by hand.
- **A fresh checkout** — the `.gitattributes` pin verified by cloning with
  `core.autocrlf=true`.
- **The commit** — CI on the pushed branch runs the new `windows-verify` job.

Registry state (`npm view`, `crates.io/api/v1/crates/...`) was **not** needed
for the chosen deliverables and is named as the next decider for D1's
`install-source` claims.

## Alternatives removed

- **Relax or delete the falsifier.** `no_row_claims_platform_independence…` and
  the `command_truth` rule could have been left out; that is the pattern that
  let the rows ship. The rule is the artifact; it stays strict.
- **Narrow `platforms` to `linux-x64-gnu` on the 23 version rows.** Honest but
  wrong: it would declare a Linux-only product on Windows. The shell call was
  the defect, not the scope.
- **Let the catalog rule imply the data fix.** Rejected: the rule would only
  have turned the release red. The rows were de-shelled so the catalog is
  truthful, not merely detected.
- **`cargo clippy --fix`.** Rejected: it deletes the helpers that the unix-only
  tests need on Linux, trading a Windows warning for a Linux test failure.
- **A repo-wide `.gitattributes`/`git add --renormalize`.** Rejected: 818 of 823
  tracked files are CRLF in this Windows working tree; the attribute is pinned
  only to the two byte-compared artifacts to avoid a mass renormalization.
- **Converge/retire the three near-copy npm publishers now.** Deferred. They
  still carry the single-read race and `NPM_TOKEN`, but npm trusted publishing
  is registered per workflow file, so converging them needs a registry change
  this study cannot verify, and "it should work" is not a decider.
- **Fix `CHANGELOG.md`'s `unreleased` headings now.** Deferred: the heading is
  the release process's, and correcting it correctly is a release-cut decision,
  not a claim fix.

## Future work must respect

1. **Adding a claim means adding its verdict.** A new manifest key the
   inventory does not classify makes `claim-inventory` exit nonzero; add the key
   to `KIND` and to the mechanism table for its schema
   (`FACADE_HELD_BY`/`CAPABILITY_HELD_BY`), or the inventory stops being
   complete. A capability `effect_truth` does not arm carries no
   `gate:effect-class`; add it to `EFFECT_ARMS` when it gains one.
2. **`platforms = []` means "runs anywhere" and disables the guard.** An
   executing row with an empty scope is `asserted`, not `witnessed`, until a
   real run records the platform. Do not read "not `witnessed`" as "broken" —
   read it as "no one has measured this yet".
3. **Freshness is frozen until `AS_OF` moves.** The evidence window compares to
   a compile-time constant; moving it is a deliberate, reviewable act.
4. **The Windows `-D warnings` job is load-bearing.** Do not gate a
   Windows-hostile test behind `#[cfg]`; supply a per-platform command or a
   unix-only test, and keep the pure logic un-gated.
5. **Byte-compared generated artifacts must be LF-pinned** in `.gitattributes`.
6. **Open holes, in priority order:** the three near-copy npm publishers
   (`cd-npm-stable-release.yml`, `cd-npm-beta-release.yml`,
   `cd-npm-release-recovery.yml`) carry the race `0c312d6` fixed and an unused
   `NPM_TOKEN`; workflow YAML is validated only by
   `local-ci`, which CI never runs and which needs `actionlint` on `PATH`.
   Closed since: `local-cd.sh`'s npm guidance (a tag release publishes over OIDC
   and needs no local login) and the `CHANGELOG.md` headings, which the 0.1.21
   cut dates.
